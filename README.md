## Идея

Дети любят смотреть видео, но YouTube устроен так, что остановиться невозможно:
рекомендации, автовоспроизведение, чужие каналы, реклама, бесконечная лента.
Родитель не может просто «включить YouTube на 20 минут».

**Булак** решает это радикально: в приложении нет поиска, нет рекомендаций,
нет подписок, нет Shorts и нет чатов. Видео попадают в библиотеку **только
тогда, когда родитель сам скопирует ссылку с YouTube и сохранит её**.
Ребёнок открывает приложение и видит красивые крупные карточки — только те,
что выбрал взрослый.

```
Родитель: копирует ссылку → вставляет в приложение → раскладывает по коллекциям
Ребёнок:  открывает приложение → листает карточки → смотрит
```

## Как это работает технически

### Воспроизведение

Приложение умеет играть видео двумя способами и выбирает подходящий автоматически:

1. **Прямой поток** (`video_player` + `youtube_explode_dart`) — приложение
   получает прямой адрес видеопотока и играет его системным плеером.
   Плюс: никакого интерфейса YouTube, никакой рекламы, ребёнок видит только
   видео. Минус: YouTube отдаёт «склеенные» потоки максимум в 360p.
2. **Встроенный плеер YouTube** (`webview_flutter`, домен `youtube-nocookie.com`) —
   резервный режим, когда поток недоступен. Плюс: выше качество.
   Минус: виден интерфейс YouTube, и YouTube может показать свою рекламу.

Режим по умолчанию — «автоматически»: сначала пробуем чистый поток, при
неудаче молча переключаемся на встроенный плеер. Родитель может зафиксировать
любой из режимов в настройках.

### Офлайн-режим

YouTube отдаёт прямой поток по временной ссылке, и на длинном видео она может
перестать работать: просмотр обрывается на середине. Поэтому в приложении есть
скачивание: родитель нажимает «Скачать» — видеофайл сохраняется в приватный
каталог приложения на телефоне, и дальше плеер играет его с диска. Интернет при
этом не нужен вообще.

Что важно знать:

- Скачивается «склеенный» поток — это **360p**, максимальное качество, которое
  YouTube отдаёт одним файлом. Раздельные видео и звук в высоком качестве
  потребовали бы сборки файла на устройстве, а это уже совсем другая история.
- Скачанное можно удалить по одному видео или все сразу; на экране «Загрузки»
  видно, сколько места занято.
- Есть настройка «Скачивать сразу при добавлении» и подсказка про трафик.

### Обмен подборками

Подборкой можно поделиться: приложение отдаёт **список ссылок** (текстом или
файлом `.bulak`) через системное «Поделиться». Другой родитель вставляет этот
список у себя — видео добавляются в библиотеку, и их можно сразу скачать.
Передаются только ссылки и подписи, сами видеофайлы никуда не отправляются.

### ⚠️ О публикации в магазинах

Скачивание видео с YouTube **не разрешено Условиями использования YouTube**,
а Google Play и App Store отклоняют приложения с такой функцией. Функция
включена по умолчанию, но её можно выключить одной опцией при сборке:

```bash
# Сборка для Google Play и App Store — без скачивания
flutter build appbundle --release --dart-define=BULAK_DISABLE_DOWNLOADS=true
```

Личная сборка (для себя и своей семьи) собирается как обычно, без флага.
Полный разбор — в [docs/legal/youtube-compliance.md](docs/legal/youtube-compliance.md).

### Хранение данных

Всё лежит **на устройстве**: список ссылок и настройки — в `shared_preferences`
в виде JSON, скачанные видеофайлы — в приватном каталоге приложения. Никакой
базы на сервере, никакой синхронизации, никаких аккаунтов.

### Приватность

- Сетевое взаимодействие — только с серверами YouTube: превью, поток,
  скачивание видео.
- PIN-код не хранится в открытом виде: только соль и `SHA-256(соль|код|bulak)`.
- Разрешений в Android ровно два: `INTERNET` и `WAKE_LOCK` (не давать экрану
  гаснуть во время просмотра). В iOS — ни одного.
- Резервная копия Android отключена (`allowBackup="false"`): ни список ссылок,
  ни скачанные видео не уезжают в облако.
- Подробности: [политика конфиденциальности](docs/legal/privacy-policy.ru.md).

## Быстрый старт

### Что нужно

- Flutter 3.47 или новее (Dart 3.13+)
- Android Studio / Xcode — для сборки под соответствующую платформу

Проверка окружения:

```bash
flutter doctor -v
```

### Запуск

```bash
git clone <адрес-репозитория> bulak
cd bulak
flutter pub get
flutter run                 # на подключённом устройстве или эмуляторе
flutter run -d <device-id>  # конкретное устройство (flutter devices)
```

### Сборка

```bash
# Android: APK для быстрой проверки
flutter build apk --release

# Android: App Bundle для Google Play
flutter build appbundle --release

# iOS: архив для App Store (только на macOS)
flutter build ipa --release
```

Для подписанной сборки Android создайте `android/key.properties` по образцу
[`android/key.properties.example`](android/key.properties.example) — подробная
инструкция в [docs/publishing/signing.md](docs/publishing/signing.md).

## Ассеты и генераторы

Шрифты, иконка и скриншоты магазинов собираются скриптами — их не нужно готовить руками.

### Шрифты

В проекте используются `Nunito` (интерфейс) и `Comfortaa` (логотип). Оба
скачиваются из репозитория Google Fonts, «замораживаются» в статические
начертания и обрезаются до нужных символов:

```bash
pip install fonttools brotli
python tools/fonts/build_fonts.py
```

### Иконка и splash

Знак «капля-родник с кнопкой воспроизведения» описан формулами в
[`tools/icon/build_assets.py`](tools/icon/build_assets.py) и разворачивается сразу
во все нужные размеры: иконку приложения, adaptive и monochrome иконки Android,
splash-экраны и графику для Google Play.

```bash
python tools/icon/build_assets.py        # весь комплект графики
dart run flutter_launcher_icons          # размеры для Android и iOS
dart run flutter_native_splash:create    # splash-экран
```

### Скриншоты для магазинов

Готовые наборы уже лежат в репозитории: `fastlane/metadata/android/*/images/phoneScreenshots/`
(Google Play, 1080 × 1920) и `fastlane/screenshots/*/` (App Store, 1290 × 2796) —
по 8 кадров на русском и английском, снятых с реальной сборки.

Пересобрать из новых снимков экрана:

```bash
python tools/screenshots/seed_emulator.py            # данные для съёмки на эмуляторе
python tools/screenshots/build_store_screenshots.py  # сборка кадров для сторов
```

`build_store_screenshots.py` вписывает вытянутый экран телефона (1:2,17) в холст
9:16, который требует Google Play, и масштабирует тот же снимок под 6,7″ для App Store.
