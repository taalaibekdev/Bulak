# App Store — «Конфиденциальность приложения» (App Privacy): ответы

Документ содержит готовые ответы для раздела **App Privacy** в App Store Connect, обоснование по каждому типу данных, ответ про отслеживание, порядок оформления privacy manifest и требования Apple к parental gate.

Приложение: «Булак» (Bulak), Bundle ID `kg.tlbk.bulak`, версия 1.0.0.

**Главный вывод:** в разделе App Privacy выбирается **«Data Not Collected»** для всех типов данных, а про отслеживание указывается, что приложение **не отслеживает** пользователя.

---

## 1. Пошаговое заполнение в App Store Connect

Путь: **App Store Connect → My Apps → Bulak → App Privacy → Edit / Get Started**.

| Шаг | Что сделать |
|---|---|
| 1 | Открыть раздел App Privacy, нажать **Get Started** |
| 2 | Ответить на вопрос «Do you or your third-party partners collect data from this app?» → **No, we do not collect data from this app** |
| 3 | Убедиться, что во всех категориях осталось значение **Data Not Collected** |
| 4 | Раздел **Data Used to Track You** → пусто (ничего не выбрано) |
| 5 | Раздел **Data Linked to You** → пусто |
| 6 | Раздел **Data Not Linked to You** → пусто |
| 7 | Проверить вопрос о Advertising Identifier (IDFA): ответ — **не используется** |
| 8 | Сохранить и опубликовать: ответы в App Privacy вступают в силу вместе с публикацией версии |
| 9 | При каждом релизе, где меняется работа с данными, раздел нужно обновлять |

> Важно: раздел App Privacy заполняется **один раз для приложения** и применяется ко всем версиям, пока вы его не измените. При добавлении аналитики или рекламы в будущем раздел обязателен к пересмотру до подачи релиза.

## 3. Отслеживание и App Tracking Transparency

| Вопрос | Ответ |
|---|---|
| Используется ли IDFA? | **Нет** |
| Используется ли App Tracking Transparency (ATT)? | **Нет.** Разрешение не запрашивается, потому что отслеживания нет |
| Отслеживается ли пользователь между приложениями или сайтами? | **Нет** |
| Передаются ли данные брокерам данных? | **Нет** |
| Используется ли рекламная атрибуция? | **Нет** |
| Есть ли рекламные SDK? | **Нет** |
| Есть ли SDK аналитики? | **Нет** |
| Есть ли SDK крашлитики? | **Нет** |
| Есть ли профилирование? | **Нет** |

**Практическое следствие.** Поскольку приложение не отслеживает пользователя, в `Info.plist` **не должно быть** ключа `NSUserTrackingUsageDescription`, а в App Store Connect вопрос об отслеживании получает отрицательный ответ. Наличие ключа ATT без фактического отслеживания может вызвать вопросы у ревьюера — ключ не добавляем.

## 4. YouTube как сторонний сервис

### 4.1. Что происходит технически

Приложение загружает публичные превью с `i.ytimg.com` и видеопоток с серверов YouTube, а также может открывать страницу встроенного плеера с домена `youtube-nocookie.com` (режим повышенной приватности YouTube). Это взаимодействие «клиент — публичный веб-сервис».

### 4.2. Почему это не «сбор данных приложением»

| Критерий Apple | Положение в «Булаке» |
|---|---|
| Приложение само формирует и передаёт данные о пользователе? | Нет |
| Приложение сохраняет данные на своих серверах? | Серверов нет |
| Приложение связывает данные с личностью пользователя? | Нет |
| Приложение использует данные для рекламы или аналитики? | Нет |
| Приложение делится данными с третьими лицами? | Нет |

Запросы к серверам YouTube порождает сам факт воспроизведения видео, выбранного родителем. Разработчик не получает, не хранит и не обрабатывает результаты этих запросов. Техническую информацию, которую получает Google как оператор сервиса (в частности IP-адрес и сведения о клиенте), обрабатывает Google в соответствии со своей политикой:

- Политика конфиденциальности Google: https://policies.google.com/privacy
- Условия использования YouTube: https://www.youtube.com/t/terms

### 4.3. Как отвечать, если ревьюер спросит

Готовая формулировка:

> The app collects no personal data and includes no analytics, advertising or crash-reporting SDKs. It performs only two kinds of network request: loading publicly available thumbnail images from `i.ytimg.com` and video streams from YouTube (Google LLC), and opening the public embedded player page from `youtube-nocookie.com` (YouTube's privacy-enhanced mode, in which YouTube sets no cookies before playback begins). Navigation inside the embedded player is restricted to YouTube and Google domains (`youtube-nocookie.com`, `youtube.com`, `ytimg.com`, `googlevideo.com`), so there is no free browsing. The app creates no identifiers, keeps no request logs and transmits nothing to the developer. All user-created data (video link list, titles, collections, viewing history, settings and the PIN hash) is stored only in the app's local storage on the device and can be erased by the user at any time using the "Reset everything" button or by deleting the app.

## 5. Privacy manifest (PrivacyInfo.xcprivacy)

Начиная с весны 2024 года Apple требует, чтобы приложения и сторонние SDK содержали файл **privacy manifest** с описанием использования «Required Reason APIs» и заявлением о том, какие данные собираются.

### Что нужно сделать для «Булака»

1. Убедиться, что в сборке есть файл `PrivacyInfo.xcprivacy` (Flutter-шаблон включает его для движка; при необходимости добавьте собственный манифест приложения).
2. В манифесте приложения указать:
   - `NSPrivacyTracking` = `false`;
   - `NSPrivacyTrackingDomains` — пустой массив;
   - `NSPrivacyCollectedDataTypes` — пустой массив;
   - `NSPrivacyAccessedAPITypes` — только те API, которые действительно используются, с корректными reason-кодами (например, `UserDefaults` с кодом `CA92.1`, если приложение читает собственные настройки).
3. Проверить, что все подключённые сторонние SDK имеют собственные манифесты. В «Булаке» сторонних SDK нет, поэтому дополнительных манифестов не требуется.
4. В Xcode: **Product → Archive**, затем проверить отчёт о приватности, если он выводится в логе сборки.

> Если в будущем добавится любой SDK, у которого нет privacy manifest, Apple отклонит сборку с указанием на отсутствующий манифест.

## 6. Требование Apple о parental gate

Guideline 1.3 (Kids Category) и 5.1.4 (Kids) требуют, чтобы в детских приложениях доступ к внешнему интернету, покупкам, ссылкам на соцсети и любым «взрослым» функциям был закрыт **родительским шлюзом** (parental gate).

### Как это реализовано в «Булаке»

| Действие, ведущее за пределы детского интерфейса | Как закрыто |
|---|---|
| Открытие страницы встроенного плеера со домена `youtube-nocookie.com` | Требуется ввод четырёхзначного PIN-кода родителя; навигация внутри плеера ограничена доменами YouTube и Google |
| Добавление нового видео по ссылке | Родительский режим, вход по PIN |
| Переименование, удаление видео | Родительский режим, вход по PIN |
| Управление коллекциями | Родительский режим, вход по PIN |
| Дневной лимит экранного времени | Родительский режим, вход по PIN |
| Смена PIN-кода | Родительский режим, вход по PIN |
| Сброс всех данных | Родительский режим, вход по PIN |
| Выход из полноэкранного плеера | Родительский замок: выход по PIN |
| Ссылки на сайт, политику конфиденциальности, поддержку (если размещены в приложении) | Открываются только из родительского режима, то есть после ввода PIN |

### Почему это соответствует требованиям Apple

1. **Шлюз стоит на входе, а не на выходе.** Ребёнок не может открыть внешний контент, потому что не может войти в родительский режим.
2. **PIN знает только родитель.** PIN-код задаёт сам родитель при первом запуске; он не хранится в открытом виде и не подсказывается в интерфейсе.
3. **Внешний контент ограничен по объёму.** Даже после ввода PIN приложение открывает не браузер, а конкретную страницу для конкретного видео — без адресной строки и без свободной навигации.
4. **Нет покупок.** Всё, что обычно требует parental gate (покупки, подписки), в приложении отсутствует, поэтому закрывать дополнительно нечего.
