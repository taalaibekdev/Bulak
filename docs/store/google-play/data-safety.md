# Google Play — Data safety: ответы для приложения «Булак»

Документ описывает, как заполнить форму **Data safety** в Play Console для приложения «Булак» (`kg.tlbk.bulak`, версия 1.0.0). Ответы сформулированы так, чтобы **точно совпадать с фактическим поведением приложения** и с текстом описания в магазине.

**Главный вывод:** по всем разделам формы указывается **«данные не собираются»** и **«данные не передаются»**. Ниже — обоснование по каждому пункту и пошаговая инструкция.

---

## 1. Пошаговое заполнение формы

В Play Console откройте: **App content → Data safety → Manage**.

| Шаг | Экран / вопрос | Ответ для «Булака» |
|---|---|---|
| 1 | Overview → Start | Нажать **Start** |
| 2 | Data collection and security → «Does your app collect or share any of the required user data types?» | **No** |
| 3 | Data collection and security → «Is all of the user data collected by your app encrypted in transit?» | **Not applicable** — данные не собираются. Если форма требует ответа, выбрать **Yes** и пояснить: сетевой трафик к серверам YouTube идёт по HTTPS |
| 4 | Data collection and security → «Do you provide a way for users to request that their data is deleted?» | **Not applicable** — данных на стороне разработчика нет. Если форма требует ответа, указать **No** и в поле пояснения написать: приложение не собирает данные, поэтому запрос на удаление не требуется; все локальные данные пользователь удаляет сам кнопкой «Сбросить всё» или удалением приложения |
| 5 | Data types | Все категории — **не отмечены** (см. раздел 2) |
| 6 | Data usage and handling | Пропускается: нет отмеченных типов данных |
| 7 | Data sharing | **No** — данные не передаются третьим лицам |
| 8 | Security practices | Отметить отсутствие сбора; в комментарии указать использование HTTPS для обращений к YouTube |
| 9 | Preview → Submit | Проверить сводку и отправить |

> После отправки форма становится «Approved» обычно в течение нескольких часов. До получения одобрения релиз в продакшен не пропускается.

## 2. Ответы по категориям данных

Форма Data safety перечисляет категории типов данных. Ниже — ответ по каждой категории и короткое обоснование, которое пригодится, если Google запросит уточнение.

| Категория в форме | Подкатегории | Ответ | Почему |
|---|---|---|---|
| **Location** | Approximate location, Precise location | **Не собирается** | Приложение не запрашивает разрешение на геолокацию и не содержит кода для её получения |
| **Personal info** | Name, Email address, User IDs, Address, Phone number, Race and ethnicity, Political or religious beliefs, Sexual orientation, Other info | **Не собирается** | Нет регистрации, нет профиля, нет форм ввода персональных данных |
| **Financial info** | User payment info, Purchase history, Credit score, Other financial info | **Не собирается** | Покупок и подписок нет, платёжные данные не запрашиваются |
| **Health and fitness** | Health info, Fitness info | **Не собирается** | Функций, связанных со здоровьем, нет |
| **Messages** | Emails, SMS or MMS, In-app messages, Other in-app messages | **Не собирается** | Чатов, комментариев и обмена сообщениями нет |
| **Photos and videos** | Photos, Videos | **Не собирается** | Видео воспроизводятся потоково с серверов YouTube и не сохраняются; доступ к галерее устройства не запрашивается |
| **Audio files** | Voice or sound recordings, Music files, Other audio files | **Не собирается** | Микрофон не используется, аудиофайлы не читаются и не сохраняются |
| **Files and docs** | Files and docs | **Не собирается** | Доступ к файловой системе не запрашивается |
| **Calendar** | Calendar events | **Не собирается** | Доступ к календарю не запрашивается |
| **Contacts** | Contacts | **Не собирается** | Доступ к контактам не запрашивается |
| **App activity** | App interactions, In-app search history, Installed apps, Other user-generated content, Other actions | **Не собирается** | История просмотра хранится только локально на устройстве и никуда не передаётся; поиска в приложении нет; список установленных приложений не читается |
| **Web browsing** | Web browsing history | **Не собирается** | Приложение не отслеживает, какие страницы открывает пользователь, и не ведёт журнал браузинга |
| **App info and performance** | Crash logs, Diagnostics, Other app performance data | **Не собирается** | Отчёты о сбоях не собираются: SDK для крашлитики не подключён |
| **Device or other IDs** | Device or other IDs | **Не собирается** | Рекламный идентификатор (AAID) и иные устойчивые идентификаторы не запрашиваются и не используются |
| **Other** | Other | **Не собирается** | Иных категорий нет |

**Итог по форме:** ни одна категория не отмечена; разделы про назначение (purpose) и передачу (sharing) не заполняются, потому что нет ни одного выбранного типа данных.

## 3. Почему приложение корректно отвечает «данные не собираются», хотя обращается к YouTube

Это самый частый вопрос при заполнении формы. Разберём его подробно — этот же текст можно использовать как пояснение, если Google запросит обоснование.

### 3.1. Что понимает Play под «сбором данных»

Play определяет сбор как **передачу данных с устройства, включая передачу третьим лицам**, которую осуществляет ваше приложение. При этом важно, что:

- сбором считается передача данных, которую приложение **инициирует и адресует** для собственных целей или для целей встроенных SDK;
- передача данных операционной системой или сетевой инфраструктурой при обычном обращении к публичному ресурсу в интернете — это не тот сбор, который подразумевает форма, если приложение не формирует, не накапливает и не сохраняет идентификаторы и не использует данные для аналитики, рекламы или профилирования.

### 3.2. Что именно делает «Булак»

| Действие приложения | Что происходит с данными |
|---|---|
| Запрос изображения-превью по адресу `i.ytimg.com` | Обычный HTTPS-запрос публичного изображения; разработчик ничего не получает и не сохраняет |
| Запрос видеопотока для воспроизведения | Потоковое воспроизведение публично доступного видео; файлы не сохраняются на устройстве |
| Открытие страницы встроенного резервного плеера YouTube | Открытие публичной веб-страницы с домена `youtube-nocookie.com` (режим повышенной приватности); воспроизведение обеспечивает Google |
| Хранение списка ссылок, названий, коллекций, истории, настроек и хэша PIN | **Только на устройстве**, без передачи куда-либо |

### 3.3. Что приложение НЕ делает

- не формирует собственный идентификатор пользователя или устройства;
- не читает и не отправляет рекламный идентификатор;
- не отправляет разработчику никаких событий, отчётов, статистики;
- не сохраняет результаты сетевых запросов в аналитическое хранилище;
- не использует данные для рекламы, профилирования, атрибуции или A/B-тестирования;
- не содержит сторонних SDK, которые собирали бы данные за нас.

### 3.4. Роль Google

Google LLC как оператор сервиса YouTube получает техническую информацию, которую любая программа передаёт при обращении к сайту (в частности IP-адрес, тип и версию операционной системы, время запроса). **Эта информация не поступает разработчику**, не сохраняется им и не используется. Отношения пользователя с Google регулируются политиками Google, а не разработчиком:

- Политика конфиденциальности Google: https://policies.google.com/privacy
- Условия использования YouTube: https://www.youtube.com/t/terms

Это же объяснение приведено в Политике конфиденциальности приложения, раздел 5.1, и в разделе о детях, пункт 7.1.

### 3.5. Что делать, если Google запросит уточнение

Если ревьюер Play усомнится в ответе, рекомендуется ответить так:

> Приложение не собирает и не передаёт пользовательские данные. Оно не содержит сторонних SDK аналитики, рекламы или крашлитики. Единственные сетевые обращения — загрузка публичных изображений-превью с `i.ytimg.com` и видеопотока с серверов YouTube (Google LLC), а также открытие публичной страницы встроенного плеера с домена `youtube-nocookie.com` в режиме повышенной приватности. Приложение не формирует идентификаторы, не сохраняет журналы запросов и не передаёт данные разработчику. Навигация внутри встроенного плеера ограничена доменами YouTube и Google (`youtube-nocookie.com`, `youtube.com`, `ytimg.com`, `googlevideo.com`), поэтому свободного браузинга в приложении нет. Все пользовательские данные (список ссылок, названия, коллекции, история просмотра, настройки, хэш PIN-кода) хранятся исключительно в локальном хранилище устройства и удаляются пользователем самостоятельно.

## 4. Раздел «Безопасность данных» (Data security)

| Вопрос раздела | Ответ | Пояснение для документации |
|---|---|---|
| Шифрование данных при передаче | Данные, создаваемые пользователем, не передаются. Сетевые обращения к YouTube выполняются по HTTPS | Незашифрованный трафик не разрешён: App Transport Security на iOS не отключается, cleartext-трафик на Android не разрешается |
| Шифрование данных при хранении | Локальные данные хранятся в приватной области приложения, доступной только самому приложению | PIN-код дополнительно хранится исключительно в виде необратимого хэша |
| Соответствие Families Policy | Да | Приложение участвует в программе Designed for Families и соблюдает её требования |
| Механизм удаления данных | Кнопка **«Сбросить всё»** в родительском режиме; полное удаление — удаление приложения | См. Политику конфиденциальности, раздел 9 |

## 5. Раздел «Доступ к данным» (разрешения приложения)

| Разрешение | Запрашивается | Назначение |
|---|---|---|
| `INTERNET` | **Да** | Загрузка превью и видеопотока с серверов YouTube, загрузка страницы встроенного плеера. Объявляется библиотеками воспроизведения видео |
| `WAKE_LOCK` | **Да** | Не давать экрану гаснуть во время просмотра видео. Объявляется библиотекой `wakelock_plus`; доступа к данным не даёт |
| `ACCESS_NETWORK_STATE` | Нет | Не используется |
| `CAMERA` | Нет | Не используется |
| `RECORD_AUDIO` | Нет | Не используется |
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | Нет | Не используется |
| `READ_CONTACTS` | Нет | Не используется |
| `READ_EXTERNAL_STORAGE` / `READ_MEDIA_*` | Нет | Не используется |
| `POST_NOTIFICATIONS` | Нет | Уведомления не отправляются |
| `AD_ID` (com.google.android.gms.permission.AD_ID) | Нет | Рекламный идентификатор не используется |
| `QUERY_ALL_PACKAGES` | Нет | Список установленных приложений не читается |

Важная деталь: собственный `android/app/src/main/AndroidManifest.xml` приложения **не объявляет ни одного разрешения**. `INTERNET` и `WAKE_LOCK` попадают в итоговый (merged) манифест из манифестов библиотек воспроизведения видео. Это нормально и не является сбором данных: `WAKE_LOCK` управляет только таймаутом экрана.

Проверка перед отправкой формы — посмотреть итоговый манифест собранной сборки, а не только исходный:

```bash
# После сборки релиза
build\app\intermediates\merged_manifests\release\AndroidManifest.xml
```

В нём должны присутствовать только `INTERNET` и `WAKE_LOCK`. Если появилось любое другое разрешение — выясните, какая зависимость его добавила, и обновите форму Data safety в том же релизе.

## 7. Типичные ошибки при заполнении

| Ошибка | Последствие | Как правильно |
|---|---|---|
| Отметить «Device or other IDs → собирается», рассуждая «IP-адрес же передаётся» | Ответ перестанет соответствовать реальности, потребуется политика удаления данных и раскрытие передачи | Приложение не формирует и не использует идентификаторы; ответ — «не собирается» |
| Отметить «App activity → App interactions» из-за локальной истории просмотра | Ложное раскрытие сбора данных | История хранится только на устройстве и не передаётся — данные не собираются |
| Указать «Data shared: Yes» из-за обращений к YouTube | Ложное раскрытие передачи | Передачи данных разработчиком нет; взаимодействие с Google описано в политике конфиденциальности |
| Заявить «Данные шифруются при хранении» | Неточность | Формулировка: данные хранятся в приватном хранилище приложения; PIN хранится в виде хэша |
| Не обновить форму после добавления новой функции | Несоответствие, риск отклонения обновления | Обновлять форму Data safety в каждом релизе, где меняется работа с данными |
| Оставить в манифесте лишние разрешения | Play покажет несоответствие декларации | Проверять манифест перед каждой сборкой |

## 8. Чек-лист перед отправкой формы

- [ ] Для всех категорий выбрано «данные не собираются».
- [ ] Раздел Data sharing — «No».
- [ ] Указано использование HTTPS для сетевых обращений.
- [ ] Указан механизм удаления данных: «Сбросить всё» и удаление приложения.
- [ ] Подтверждено соответствие Families Policy.
- [ ] Ответы совпадают с описанием в сторе и с политикой конфиденциальности.
- [ ] В итоговом (merged) Android-манифесте только разрешения `INTERNET` и `WAKE_LOCK`.
- [ ] Ссылка на политику конфиденциальности в Play Console заполнена и открывается.
- [ ] Форма отправлена и получила статус «Approved» до подачи релиза в продакшен.
