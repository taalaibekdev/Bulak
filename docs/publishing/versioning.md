# Версионирование приложения «Булак»

Документ описывает, как менять версию приложения, как версия из `pubspec.yaml` превращается в версии для Android и iOS, какие правила семантического версионирования применять в мобильном проекте и как вести changelog.

---

## 1. Где хранится версия

Единственный источник правды — поле `version` в `pubspec.yaml`:

```yaml
version: 1.0.0+1
```

Формат: `MAJOR.MINOR.PATCH+BUILD`

| Часть | Смысл | Пример |
|---|---|---|
| `MAJOR` | Несовместимые изменения, смена модели данных, крупный перезапуск | `2.0.0` |
| `MINOR` | Новые функции, обратная совместимость сохранена | `1.1.0` |
| `PATCH` | Исправления ошибок, мелкие улучшения | `1.0.1` |
| `BUILD` | Номер сборки; увеличивается при **каждой** загрузке в стор | `+7` |

Пример: `version: 1.2.3+45` — версия 1.2.3, сорок пятая сборка.

## 2. Как версия попадает в платформы

Flutter автоматически передаёт значения из `pubspec.yaml` в конфигурацию Android и iOS. В `android/app/build.gradle.kts` это уже настроено:

```kotlin
defaultConfig {
    versionCode = flutter.versionCode
    versionName = flutter.versionName
}
```

| `pubspec.yaml` | Android | iOS |
|---|---|---|
| `1.0.0` | `versionName = "1.0.0"` | `CFBundleShortVersionString = "1.0.0"` |
| `+1` | `versionCode = 1` | `CFBundleVersion = "1"` |

### Что показывается пользователю

| Платформа | Что видит пользователь | Где показывается |
|---|---|---|
| Google Play | `versionName` (`1.0.0`) | На странице приложения в разделе «О приложении» |
| App Store | `CFBundleShortVersionString` (`1.0.0`) | На странице приложения в разделе «Версия» |
| Android-система | `versionName` | Настройки → Приложения → Булак |
| iOS-система | `CFBundleShortVersionString` | Настройки → Основные → Хранилище |

### Почему номер сборки критичен

| Платформа | Требование | Что будет при нарушении |
|---|---|---|
| Google Play | `versionCode` должен быть **больше** любого ранее загруженного | Ошибка «Version code 1 has already been used» |
| App Store | `CFBundleVersion` должен быть **больше** предыдущего в рамках той же версии | Ошибка «The bundle version must be higher than the previously uploaded version» |

**Правило:** номер сборки монотонно возрастает и **никогда не уменьшается**. Даже если вы откатили код до предыдущего состояния, номер сборки всё равно должен быть новым.

> Для App Store: `CFBundleVersion` должен увеличиваться **внутри одной** `CFBundleShortVersionString`. Например, для версии 1.0.0 это могут быть сборки 1, 2, 3; после выпуска 1.0.1 нумерация сборок может начаться снова с 1, но проще продолжать сквозную нумерацию — так меньше путаницы.

## 3. Как изменить версию

### Вариант 1: Правка `pubspec.yaml` (рекомендуется)

```yaml
version: 1.0.1+2
```

Затем обычная сборка:

```bash
flutter build appbundle --release
flutter build ipa --release
```

### Вариант 2: Флаги командной строки

```bash
flutter build appbundle --release --build-name=1.0.1 --build-number=2
flutter build ipa --release --build-name=1.0.1 --build-number=2
```

Полезно в CI, где версия приходит из тега git.

### Что не нужно делать

| Не делать | Почему |
|---|---|
| Править `versionName` / `versionCode` в `android/app/build.gradle.kts` вручную | Значения перезаписываются Flutter из `pubspec.yaml`; возникнет путаница |
| Править `CFBundleShortVersionString` / `CFBundleVersion` в `Info.plist` вручную | То же: Flutter подставляет значения при сборке |
| Собирать релиз с версией, которая уже загружалась | Стор отклонит сборку |

### Проверка версии в собранном артефакте

```bash
# Android
aapt2 dump badging build/app/outputs/flutter-apk/app-release.apk | findstr version

# iOS
/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" build/ios/iphoneos/Runner.app/Info.plist
/usr/libexec/PlistBuddy -c "Print :CFBundleVersion" build/ios/iphoneos/Runner.app/Info.plist
```

## 4. Семантическое версионирование для мобильного приложения

Семантика в мобильном приложении совпадает с библиотечной, но с практическими оговорками: **изменения модели локальных данных — это всегда MAJOR**, потому что они влияют на пользовательские данные.

### 4.1. Когда увеличивать MAJOR

| Ситуация | Пример для «Булака» |
|---|---|
| Смена модели локальных данных, требующая миграции | Переход от плоского списка ссылок к структуре «профили детей + коллекции» без обратной совместимости |
| Удаление или принципиальное изменение функции | Удаление истории просмотра |
| Несовместимое изменение минимальных требований | Подъём minSdk с 23 до 26, отказ от iOS 13 |
| Смена юридической или продуктовой модели | Введение аккаунтов и облачной синхронизации |

### 4.2. Когда увеличивать MINOR

| Ситуация | Пример для «Булака» |
|---|---|
| Новая функция, совместимая с прежними данными | Добавление нескольких профилей детей |
| Новый язык интерфейса | Добавление казахского языка |
| Новая настройка родительского режима | Расписание лимита по дням недели |
| Существенное улучшение существующей функции | Автоматическое определение превью для добавленных ссылок |

### 4.3. Когда увеличивать PATCH

| Ситуация | Пример для «Булака» |
|---|---|
| Исправление ошибки | Исправлен баг: дневной лимит сбрасывался при повороте экрана |
| Мелкое улучшение интерфейса | Увеличен размер кнопки паузы |
| Исправление опечатки в тексте | Опечатка в экране «На сегодня всё» |
| Обновление зависимостей без изменения поведения | Обновление `cupertino_icons` |
| Правка юридического текста внутри приложения | Уточнение формулировки в разделе «О приложении» |

### 4.4. Практические примеры для версии 1.0.0

| Изменение | Новая версия | Почему |
|---|---|---|
| Исправлен баг с лимитом времени | `1.0.1+2` | PATCH: поведение исправлено, данных не касается |
| Добавлены профили для двух детей | `1.1.0+3` | MINOR: новая функция |
| Добавлен экспорт списка ссылок в файл | `1.1.0+4` | MINOR: новая функция |
| Переработана модель хранения коллекций с миграцией | `2.0.0+5` | MAJOR: меняется модель данных |

### 4.5. Правила, которые стоит соблюдать

1. **Один релиз — один инкремент.** Не объединяйте MINOR и PATCH в одном выпуске: выпускайте 1.1.0, а исправления — в 1.1.1.
2. **Номер сборки растёт всегда.** Даже для выпуска ровно того же кода (например, при повторной загрузке после отклонения).
3. **Нулевая MAJOR-версия — не для продакшена.** `0.x` означает «в разработке»; релиз в стор начинается с `1.0.0`.
4. **Версия в `pubspec.yaml` и версия в сторе должны совпадать.** Не используйте разные номера для Android и iOS без крайней необходимости.
5. **Миграция данных — повод для MAJOR.** Пользователь не должен потерять свои ссылки при обновлении: если миграция невозможна, это MAJOR и об этом нужно предупредить в changelog.

## 5. Hotfix и откат

### 5.1. Процесс hotfix

| Шаг | Действие |
|---|---|
| 1 | Определить, что баг критический (краш, потеря данных, невозможность смотреть видео) |
| 2 | Ветка от тега текущей выпущенной версии |
| 3 | Минимальное исправление, без побочных улучшений |
| 4 | Тесты + проверка на реальном устройстве |
| 5 | Увеличить PATCH и номер сборки: `1.0.1+2` |
| 6 | Собрать, подписать, загрузить |
| 7 | В Play — ускоренный выпуск (можно начать сразу со 100 %, если баг критический); в App Store — запросить ускоренное ревью (Expedited Review), обосновав критичность |
| 8 | Записать инцидент: причина, исправление, как предотвратить повтор |

### 5.2. Откат версии

**Откатить выпущенную версию в магазинах невозможно.** Apple и Google не позволяют вернуть предыдущую версию для новых установок. Что можно сделать:

| Платформа | Возможные действия |
|---|---|
| Google Play | Остановить поэтапный выпуск (halt rollout), если он ещё идёт. Выпустить исправление с новым versionCode |
| App Store | Остановить поэтапный выпуск (Pause Phased Release). В экстренном случае — снять приложение с продажи (Remove from Sale) и затем выпустить исправление |
| Оба | Отключить проблемную функцию на стороне приложения (если она управляется локально), выпустить исправление как можно быстрее |

### 5.3. Поэтапный выпуск как страховка

| Платформа | Механизм | Рекомендация |
|---|---|---|
| Google Play | Staged rollout | Начинать с 10–20 %, останавливаться при росте крашей, расширять до 100 % в течение 3–7 дней |
| App Store | Phased Release | Включать на 7 дней: Apple сама распределит обновление по пользователям |

Оба механизма работают только для автоматических обновлений; новые пользователи могут получить новую версию сразу.

## 6. Changelog: практика

### 6.1. Где хранить

| Что | Где |
|---|---|
| Полный технический changelog | Рекомендуется файл `docs/CHANGELOG.md` в формате Keep a Changelog |
| Текст «Что нового» для Google Play | Play Console → Release notes (до 500 символов), отдельно для каждого языка |
| Текст «Что нового» для App Store | App Store Connect → What's New (до 4000 символов), отдельно для каждой локализации |

> Файл `docs/CHANGELOG.md` в этом комплекте документации не создаётся: его стоит завести при первом обновлении после релиза 1.0.0.

### 6.2. Формат записи changelog

```markdown
## [1.1.0] — 2025-03-15

### Добавлено
- Профили для нескольких детей: каждый ребёнок видит свою подборку видео.

### Изменено
- Увеличены кнопки управления в плеере.

### Исправлено
- Дневной лимит времени больше не сбрасывается при повороте экрана.

## [1.0.0] — 2025-01-20

### Добавлено
- Первый публичный релиз: сетка с крупными карточками, коллекции, избранное,
  история просмотра, дневной лимит времени, полноэкранный детский плеер,
  родительский режим под PIN-кодом.
```

### 6.3. Текст «Что нового» для Google Play (лимит 500 символов)

Пишите **для родителей**, а не для разработчиков. Без технического жаргона, без номеров задач, без слов «рефакторинг» и «багфикс».

**Русская версия:**

```
Что нового в версии 1.0.0

• Первый выпуск «Булака».
• Родитель добавляет видео по ссылке — ребёнок смотрит только их.
• Коллекции с эмодзи: «Мультики», «Учёба», «Музыка».
• Избранное и история просмотра.
• Дневной лимит времени с добрым экраном «На сегодня всё».
• Родительский режим под PIN-кодом.

Спасибо, что выбрали «Булак»! Пишите нам: support@tlbk.kg
```

**Английская версия:**

```
What's new in version 1.0.0

• The first release of Bulak.
• A parent adds videos by link — a child watches only those.
• Emoji collections: Cartoons, Learning, Music.
• Favourites and viewing history.
• A daily screen-time limit with a kind "That's all for today" screen.
• Parent mode protected by a PIN.

Thank you for choosing Bulak! Write to us: support@tlbk.kg
```

### 6.4. Текст «Что нового» для App Store (лимит 4000 символов)

Используйте тот же текст, что для Play, при необходимости чуть подробнее. Apple допускает больше символов, но короткий читаемый текст работает лучше длинного.

**Русская версия:**

```
Первый выпуск «Булака» — спокойного видео для детей.

Что уже есть:
• Родитель сохраняет ссылки на видео, ребёнок смотрит только их.
• Коллекции с эмодзи и цветом: «Мультики», «Учёба», «Музыка».
• Избранное и история просмотра.
• Дневной лимит экранного времени с добрым экраном «На сегодня всё».
• Полноэкранный плеер с крупными детскими кнопками.
• Родительский режим под PIN-кодом: добавление, переименование, удаление видео,
  коллекции, лимит времени и сброс данных.

Мы не показываем свою рекламу и не собираем персональные данные: всё, что вы
добавите, хранится только на вашем устройстве.

Есть вопросы или предложения? Напишите нам: support@tlbk.kg
```

**Английская версия:**

```
The first release of Bulak — calm video time for kids.

What is already here:
• A parent saves video links; a child watches only those.
• Emoji and colour collections: Cartoons, Learning, Music.
• Favourites and viewing history.
• A daily screen-time limit with a kind "That's all for today" screen.
• A full-screen player with big, child-friendly buttons.
• Parent mode protected by a PIN: add, rename and delete videos, manage
  collections, set the time limit and reset data.

We do not show our own advertising and we do not collect personal data:
everything you add stays on your device.

Questions or suggestions? Write to us: support@tlbk.kg
```

### 6.5. Правила хорошего changelog

| Правило | Пояснение |
|---|---|
| Писать для пользователя | «Дневной лимит больше не сбрасывается» вместо «Исправлен баг в TimeLimitProvider» |
| Начинать с главного | Первый пункт — самое важное изменение |
| Не перечислять всё | 3–6 пунктов достаточно; мелочи не упоминаем |
| Локализовать | Отдельный текст для каждого языка листинга |
| Не обещать будущее | Только то, что уже есть в этой версии |
| Не упоминать внутренние детали | Ни номеров задач, ни названий файлов, ни имён разработчиков |
| Указывать контакт | E-mail поддержки в конце — повышает доверие и снижает негативные отзывы |
| Не писать «исправлены мелкие ошибки» | Это бессмысленная фраза; лучше конкретика или ничего |

### 6.6. Чек-лист перед публикацией версии

- [ ] `pubspec.yaml` содержит новую версию и увеличенный номер сборки.
- [ ] Версия в собранном AAB проверена командой `aapt2 dump build`.
- [ ] Версия в собранном IPA проверена через `PlistBuddy`.
- [ ] Release notes подготовлены на русском и английском.
- [ ] Release notes укладываются в лимит (500 символов для Play).
- [ ] Release notes не содержат технического жаргона.
- [ ] Changelog обновлён (если ведётся).
- [ ] Тег в git проставлен по версии (например, `v1.0.1`).
- [ ] Номер сборки не совпадает ни с одной ранее загруженной сборкой.
